Une feuille de route d’apprentissage pour les développeurs mobiles : d’abord les bases communes, puis iOS, Android, Flutter et React Native, et enfin les pratiques d’ingénierie qui permettent à une app de continuer à fonctionner après sa première version. Elle compte 124 sujets. Chacun indique ce qu’il faut apprendre, quels sujets apprendre d’abord, un petit projet pour s’exercer et où l’apprendre : uniquement des sources primaires, comme la documentation d’Apple, d’Android, de Flutter, de Dart, de React Native et d’Expo, les propositions Swift Evolution, les RFC et l’OWASP. Le contenu est à jour en octobre 2026 : Swift 6.4 et Xcode 27, le SDK iOS 27 avec son cycle de vie des scenes obligatoire et Liquid Glass, Android 16, Flutter 3.47 avec Dart 3.13, et React Native 0.88 avec Expo SDK 58.

Vous pouvez lire la feuille de route ici, sur GitHub, planifier votre propre parcours dans le terminal avec la commande `roadmap`, ou la suivre dans l’app RoadmapExplorer pour iPhone, iPad et Mac.

## Points forts

- **Un parcours, pas une liste** — chaque sujet nomme les sujets dont il a besoin ; `roadmap path` transforme donc un objectif en liste ordonnée de sujets à apprendre, en ignorant ceux que vous connaissez déjà.
- **Uniquement des sources primaires** — 301 liens vers la documentation officielle et les standards. Un linter rejette les blogs, les cours et les dépôts personnels, et la vérification des liens interroge chaque URL toutes les semaines.
- **Des plateformes à jour** — le cycle de vie UIScene que doivent adopter les apps compilées avec le SDK iOS 27, Liquid Glass (la dérogation de compatibilité est ignorée pour les builds iOS 27), la sécurité face aux data races de Swift 6, les règles Android 16 pour les grands écrans, la migration de Flutter vers UIScene et la New Architecture de React Native, la seule disponible depuis la 0.82.
- **De la pratique pour chaque sujet** — un petit projet par sujet, la plupart prolongeant la même app de recettes, de sorte que la pratique s’accumule.
- **Un seul format, vérifié** — les sujets sont du Markdown simple à la structure fixe ; les mêmes fichiers alimentent donc GitHub, la ligne de commande, l’app et la bibliothèque [RoadmapKit](#utiliser-la-bibliothèque) ; les tests échouent quand un prérequis manque, qu’une boucle apparaît ou qu’un nombre de la documentation ne correspond plus.

## Démarrage rapide

**1. Récupérer la feuille de route**

```sh
git clone https://github.com/muhittincamdali/mobile-developer-roadmap.git
cd mobile-developer-roadmap
```

Il vous faut Swift 6.2 ou une version ultérieure : Xcode 26 ou ultérieur sur un Mac, ou une [toolchain Swift](https://www.swift.org/install/) sous Linux. Pour lire les fichiers Markdown, vous n’avez besoin de rien.

**2. Planifier un parcours vers un objectif**

Indiquez le sujet que vous voulez atteindre et les sujets que vous connaissez déjà :

```sh
swift run roadmap path ios/swift-6-mode --known foundations/programming,ios/swift
```

La première exécution compile l’outil. Il affiche ensuite les sujets dans l’ordre où il faut les apprendre :

```console
$ swift run roadmap path ios/swift-6-mode --known foundations/programming,ios/swift
Path to ios/swift-6-mode: 7 topics

1. foundations/http · beginner · HTTP and web APIs
2. foundations/json · beginner · JSON and data formats
3. foundations/async · beginner · Asynchronous code and the main thread
4. ios/optionals-and-errors · beginner · Optionals and error handling
5. ios/networking · beginner · Networking with URLSession and Codable
6. ios/concurrency · intermediate · Swift concurrency
7. ios/swift-6-mode · intermediate · The Swift 6 language mode  ← goal

Skipped, already known: foundations/programming, ios/swift
```

**3. Ouvrir le premier sujet**

```sh
swift run roadmap show foundations/http
```

Cela affiche ce qu’il faut apprendre, le projet d’exercice, les sujets auxquels il mène et ses liens. Notez les sujets terminés dans un fichier texte, un ID par ligne, puis demandez ce que vous pouvez commencer ensuite :

```sh
printf 'foundations/programming\nios/swift\nfoundations/http\n' > my-progress.txt
swift run roadmap next --known-file my-progress.txt --track ios
```

## Commands

| Commande | Ce qu’elle fait |
| --- | --- |
| `roadmap tracks` | Sujets par parcours et par niveau |
| `roadmap list --track flutter --stage beginner` | Liste les ID, les niveaux et les titres ; accepte aussi `--search` |
| `roadmap show react-native/new-architecture` | Un sujet avec son exercice, ses prérequis, les sujets qui en dépendent et ses liens |
| `roadmap path <ID>... --known <IDs>` | Les sujets ordonnés pour atteindre jusqu’à 32 objectifs ; accepte aussi `--known-file` |
| `roadmap next --known-file my-progress.txt` | Les sujets dont vous connaissez déjà les prérequis ; accepte aussi `--track` |
| `roadmap graph --track android` | Un parcours sous forme d’organigramme Mermaid, que GitHub affiche |
| `roadmap lint` | Vérifie les fichiers de la feuille de route ; code de sortie 1 au moindre problème |

Exécutez `swift run roadmap --help` pour la liste complète. Une entrée invalide, comme un parcours inconnu ou une ligne du fichier de progression qui n’est pas un ID de sujet, est signalée par le code de sortie 2 au lieu de provoquer un plantage ; un ID bien formé qui ne figure pas dans la feuille de route l’est par le code de sortie 1.

## Exemple : un sujet

Chaque sujet est une section Markdown avec un ID, un niveau, ses prérequis, un résumé, un projet d’exercice et ses sources. Voici `ios/app-life-cycle` dans [roadmap/ios.md](roadmap/ios.md) :

```markdown
## ios/app-life-cycle: The app and scene life cycle

**Stage:** beginner · **Needs:** ios/swiftui

- An app has one process and one or more scenes (windows); each scene becomes active, inactive
  and enters the background on its own.
- In SwiftUI, `App` and `WindowGroup` are scene-based, and `scenePhase` reports the changes.
- UIKit apps move from `UIApplicationDelegate` window code to `UISceneDelegate`. Apple's TN3187
  says that from the release after iOS 26, an app built with the latest SDK that does not
  adopt the scene life cycle will not launch: with Xcode 27 and the iOS 27 SDK this is required.

**Practice:** Save a draft when the scene goes to the background and restore it on the next launch.

**Learn from:**

- [TN3187: Migrating to the UIKit scene-based life cycle](https://developer.apple.com/documentation/technotes/tn3187-migrating-to-the-uikit-scene-based-life-cycle)
- [Managing your app's life cycle](https://developer.apple.com/documentation/uikit/managing-your-app-s-life-cycle)
- [ScenePhase](https://developer.apple.com/documentation/swiftui/scenephase)
```

## Utiliser la bibliothèque

La bibliothèque `RoadmapKit` lit, vérifie et planifie les fichiers de la feuille de route depuis votre propre code Swift. Ajoutez-la avec Swift Package Manager :

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/mobile-developer-roadmap.git", from: "2.0.0")
],
targets: [
    .target(name: "MyLearningTool", dependencies: [
        .product(name: "RoadmapKit", package: "mobile-developer-roadmap")
    ])
]
```

```swift
import Foundation
import RoadmapKit

let roadmap = try Roadmap.load(from: URL(fileURLWithPath: "roadmap"))
let plan = try roadmap.plan(to: ["flutter/architecture"], knowing: ["foundations/programming"])
for (number, topic) in plan.steps.enumerated() {
    print(number + 1, topic.id, topic.title)
}
```

La lecture est bornée (1 MiB par fichier, 500 sujets par fichier, 32 prérequis et 16 liens par sujet, 100 problèmes signalés par fichier), et chaque problème de format revient sous la forme d’un `Diagnostic` avec un fichier et une ligne plutôt que d’une exception.
