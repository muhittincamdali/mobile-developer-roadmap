A learning roadmap for mobile developers: the shared foundations, then iOS, Android, Flutter and
React Native, then the engineering practice that keeps an app working after its first release. It
has 124 topics. Each one says what to learn, which topics to learn first, a small project to
practise with, and where to learn it from: only primary sources, such as the Apple, Android,
Flutter, Dart, React Native and Expo documentation, Swift Evolution proposals, RFCs and OWASP. The
content is current for October 2026: Swift 6.4 and Xcode 27, the iOS 27 SDK with its required
scene life cycle and Liquid Glass, Android 16, Flutter 3.47 with Dart 3.13, and React Native 0.88
with Expo SDK 58.

You can read the roadmap here on GitHub, plan your own path through it in the terminal with the
`roadmap` command, or follow it in the RoadmapExplorer app for iPhone, iPad and Mac.

## Highlights

- **A path, not a list** — every topic names the topics it needs, so `roadmap path` turns a goal
  into the ordered list of topics to learn, skipping the ones you already know.
- **Primary sources only** — 301 links to official documentation and standards. A linter rejects
  blogs, courses and personal repositories, and the link checker requests every URL each week.
- **Current platforms** — the UIScene life cycle that apps built with the iOS 27 SDK must adopt,
  Liquid Glass (the compatibility opt-out is ignored for iOS 27 builds), Swift 6 data-race safety,
  Android 16 large-screen rules, Flutter's UIScene migration, and the React Native New
  Architecture, which is the only one since 0.82.
- **Practice for every topic** — one small project per topic, most of them building on the same
  recipe app, so the practice adds up.
- **One format, checked** — topics are plain Markdown with a fixed structure, so the same files
  feed GitHub, the command line, the app and the [RoadmapKit](#use-the-library) library; tests
  fail when a need is missing, a loop appears or a count in the docs drifts.

## Quick start

**1. Get the roadmap**

```sh
git clone https://github.com/muhittincamdali/mobile-developer-roadmap.git
cd mobile-developer-roadmap
```

You need Swift 6.2 or later: Xcode 26 or later on a Mac, or a [Swift toolchain](https://www.swift.org/install/)
on Linux. Reading the Markdown files needs nothing at all.

**2. Plan a path to a goal**

Name the topic you want to reach and the topics you already know:

```sh
swift run roadmap path ios/swift-6-mode --known foundations/programming,ios/swift
```

The first run builds the tool. It prints the topics in the order to learn them:

```console
$ swift run roadmap path ios/swift-6-mode --known foundations/programming,ios/swift
Path to ios/swift-6-mode: 7 topics

1. foundations/http · beginner · HTTP and web APIs
2. foundations/json · beginner · JSON and data formats
3. foundations/async · beginner · Asynchronous code and the main thread
4. ios/optionals-and-errors · beginner · Optionals and error handling
5. ios/networking · beginner · Networking with URLSession and Codable
6. ios/concurrency · intermediate · Swift concurrency
7. ios/swift-6-mode · intermediate · The Swift 6 language mode  ← goal

Skipped, already known: foundations/programming, ios/swift
```

**3. Open the first topic**

```sh
swift run roadmap show foundations/http
```

This prints what to learn, the practice project, the topics it leads to and its links. Keep the
topics you finish in a text file, one ID per line, and ask what you can start next:

```sh
printf 'foundations/programming\nios/swift\nfoundations/http\n' > my-progress.txt
swift run roadmap next --known-file my-progress.txt --track ios
```

## Commands

| Command | What it does |
| --- | --- |
| `roadmap tracks` | Topics per track and stage |
| `roadmap list --track flutter --stage beginner` | Lists IDs, stages and titles; also `--search` |
| `roadmap show react-native/new-architecture` | One topic with its practice, needs, dependents and links |
| `roadmap path <ID>... --known <IDs>` | The ordered topics to reach up to 32 goals; also `--known-file` |
| `roadmap next --known-file my-progress.txt` | Topics whose needs you already know; also `--track` |
| `roadmap graph --track android` | A track as a Mermaid flowchart, which GitHub renders |
| `roadmap lint` | Checks the roadmap files; exit status 1 on any problem |

Run `swift run roadmap --help` for the full list. Invalid input, such as an unknown track or a
line in the progress file that is not a topic ID, is reported with exit status 2 instead of
crashing; a well-formed ID that is not in the roadmap, with exit status 1.

## Example: one topic

Each topic is a Markdown section with an ID, a stage, its needs, a summary, a practice project and
its sources. This is `ios/app-life-cycle` in [roadmap/ios.md](roadmap/ios.md):

```markdown
## ios/app-life-cycle: The app and scene life cycle

**Stage:** beginner · **Needs:** ios/swiftui

- An app has one process and one or more scenes (windows); each scene becomes active, inactive
  and enters the background on its own.
- In SwiftUI, `App` and `WindowGroup` are scene-based, and `scenePhase` reports the changes.
- UIKit apps move from `UIApplicationDelegate` window code to `UISceneDelegate`. Apple's TN3187
  says that from the release after iOS 26, an app built with the latest SDK that does not
  adopt the scene life cycle will not launch: with Xcode 27 and the iOS 27 SDK this is required.

**Practice:** Save a draft when the scene goes to the background and restore it on the next launch.

**Learn from:**

- [TN3187: Migrating to the UIKit scene-based life cycle](https://developer.apple.com/documentation/technotes/tn3187-migrating-to-the-uikit-scene-based-life-cycle)
- [Managing your app's life cycle](https://developer.apple.com/documentation/uikit/managing-your-app-s-life-cycle)
- [ScenePhase](https://developer.apple.com/documentation/swiftui/scenephase)
```

## Use the library

The `RoadmapKit` library reads, checks and plans the roadmap files from your own Swift code. Add
it with Swift Package Manager:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/mobile-developer-roadmap.git", from: "2.0.0")
],
targets: [
    .target(name: "MyLearningTool", dependencies: [
        .product(name: "RoadmapKit", package: "mobile-developer-roadmap")
    ])
]
```

```swift
import Foundation
import RoadmapKit

let roadmap = try Roadmap.load(from: URL(fileURLWithPath: "roadmap"))
let plan = try roadmap.plan(to: ["flutter/architecture"], knowing: ["foundations/programming"])
for (number, topic) in plan.steps.enumerated() {
    print(number + 1, topic.id, topic.title)
}
```

Reading is bounded (1 MiB per file, 500 topics per file, 32 needs and 16 links per topic, 100
reported problems per file), and every format problem comes back as a `Diagnostic` with a file and
line instead of an exception.
